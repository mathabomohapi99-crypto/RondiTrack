# RondiTrack: web-next (Next.js 16)

The RondiTrack frontend rebuilt on Next.js 16.4.1 (App Router). Pages are Server Components. The browser never calls the API: the Next.js server does, with a token kept in an encrypted, HttpOnly cookie that the browser cannot read.

## Running it

1. Start the API: `dotnet run --project API --launch-profile http` (port 5134).
2. Copy `.env.example` to `.env.local` and fill in:
   - `API_BASE_URL` (e.g. `http://localhost:5134`)
   - `SESSION_SECRET`, made with `node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"`
3. In `web-next/`:
   ```bash
   npm install
   npm run gen:api   # regenerates src/types/schema.d.ts from the running API
   npm run dev       # http://localhost:3000
   npm test
   npm run build
   ```

Demo users (created by registering, then roles set in the database): `lerato.demo@example.com` (Treasurer of Ubuntu Savers, Member of Festive Grocery Club) and `sipho.demo@example.com` (Member of Ubuntu Savers only). Password for both: `Demo-password-123` (a throwaway demo value).

**Why neither variable starts with `NEXT_PUBLIC_`:** Next.js copies every `NEXT_PUBLIC_` variable into the JavaScript sent to the browser. The API address and the encryption secret must stay on the server. A leaked `SESSION_SECRET` would let anyone forge a session cookie.

## API check

| # | Question | My answer |
|---|----------|-----------|
| 1 | Does the list return my role per stokvel? What for a user in no stokvels? | **No, so I fixed the API.** `GET /api/stokvels` is platform-admin only (403 for everyone else) and has no role. I added `GET /api/me/stokvels`: every stokvel I belong to with `myRole`, paid and owed this cycle and the next payout date. Lerato gets `Treasurer` for Ubuntu Savers and `Member` for Festive Grocery Club. A user in no stokvels gets **200 with `[]`** (tested). |
| 2 | Non-member vs missing id vs `not-a-guid`: same status? | **Yes, all three are 404.** A non-member and a missing id return the same problem+json (an existing test compares them). `not-a-guid` does not match the `{stokvelId:guid}` route, so it is a plain 404 with an empty body. The page shows the same not-found page for all three. |
| 3 | Which header carries the refresh token? | `Set-Cookie: rondi_refresh=<token>; expires=...; path=/api/auth; secure; samesite=strict; httponly`, read with `getSetCookie()` in `scripts/check-login.mjs`. Output: status 200, body keys `accessToken`, `expiresAtUtc`, `tokenType`. The refresh token is not in the body. |
| 4 | How long does the access token live? What when expired? | **10 minutes** (`Jwt:AccessTokenMinutes`). The API then returns 401 problem+json and the app sends the person to `/login?expired=1` (no refresh until Day 3). The session cookie lasts 7 days, but the access token inside it only works for 10 minutes. |
| 5 | Which IP does the API see for ten different people? | The Next.js server's IP, every time. The API has no login rate limit yet (6.1 gap), so nothing breaks today. See Known gaps. |
| 6 | Does `GET /stokvels/{id}` return member count and a cycle summary? | Member count: yes already. My role and the cycle summary: **no, so I added them** (`myRole` and `currentCycle` with collected amount and next payout date). |

**API fixes, with tests:** `GET /api/me`, `GET /api/me/stokvels` (new `MeController` and `MyStokvelsService`) and the extra fields on `GET /api/stokvels/{id}`. Tests are in `RondiTrack.Tests/MyStokvelsTests.cs`: me, 401 without a token, an empty list for a user in no stokvels, the role per stokvel (and nobody else's stokvels), paid/owed, and detail with role and cycle.

## Routes

| Route | What it shows | When there is nothing / not theirs |
|-------|---------------|------------------------------------|
| `/` | Redirects to `/dashboard/member` when signed in, `/login` when not | n/a |
| `/login` | Sign-in (Server Action + `useActionState`) | Wrong password shows the message and the reference |
| `/dashboard/member` | Every stokvel I belong to: paid, owed, next payout | Empty state |
| `/dashboard/treasurer` | Only stokvels where I am Treasurer, each linking to its detail page | Empty state (not an error, not a 403) |
| `/stokvels` | My stokvels as cards with my role | Empty state |
| `/stokvels/[id]` | Name, contribution, my role, member count, current cycle summary | `not-found.tsx` (same page for non-member, missing and malformed id) |

Data: `GET /api/me/stokvels` (one call builds the stokvel list and both dashboards, because it returns my role per stokvel), `GET /api/stokvels/{id}`, and `GET /api/me` at sign-in.

Because `loading.tsx` lets the page start streaming first, `notFound()` arrives as HTTP 200 with a `noindex` meta tag. That is how streaming works in Next.js 16, so I checked what the person sees, not the status code.

The sidebar has four links: Home, My stokvels, Member dashboard and Treasurer dashboard. `/stokvels/[id]` needs an id, so it is reached from the lists.

## The treasurer dashboard

RondiTrack has no "treasurer" users. It has users who are Treasurer of *some* stokvels, so one person can be Treasurer of one stokvel and Member of another. `/dashboard/treasurer` is therefore a filtered view that everyone may open, not a page behind a role check. It uses the pure function `stokvelsWhereTreasurer(list)` (`src/lib/stokvelsWhereTreasurer.ts`), tested in Vitest for a mixed list, a Treasurer-nowhere list and an empty list.

**Why the session stores no role:** a role belongs to a person *and a stokvel*. One role in the cookie or the token would be wrong for at least one of their stokvels, and it would go stale when a chairperson changes it. (The API's access token has no stokvel role either, for the same reason.) So the role comes from the API's answer for each stokvel, every time.

The sidebar shows all four links to everyone. Hiding "Treasurer" from people who are Treasurer nowhere would only be a convenience. The page is safe either way, because the API decides what each person may see.

## The client boundary

Files with `'use client'`, and the one reason each needs it:

- `src/components/StokvelCard.tsx`: the Show details toggle uses `useState`.
- `src/app/(auth)/login/LoginForm.tsx`: it uses `useActionState`, a React hook.
- `src/app/(app)/error.tsx`: error pages must be Client Components, and Try again uses `onClick`.

No Client Component imports `session.ts` or `api.ts`, and both start with `import 'server-only'`, so doing it breaks the build. `LoginForm` imports the Server Action from `actions.ts`. A `'use server'` import becomes only a reference to the server function, so the session code does not enter the browser bundle.

## Known gaps

- **Login rate limit (Q5):** the API has no login rate limit yet. Once it has a per-IP one, every sign-in will come from the Next.js server's IP, so all users would share one limit and could lock each other out. Not fixed this week.
- **Error messages in production:** Next.js hides the message of errors thrown in Server Components in production builds and shows only a digest. The friendly message and reference show fully in `npm run dev`; in `npm start` the page may show only the generic text and the digest as the reference.
- **Next payout date** is calculated (cycle start + one period) because the data model has no payout schedule.
- **Seed data:** my development database has leftover test data (for example Ubuntu Savers has 8 members with a maximum of 6, and several open cycles). The API treats the open cycle with the highest cycle number as the current one.
- **Platform admins:** the API lets a platform admin open any stokvel, so `myRole` can be null there and the page says so.
- **Roles** are set directly in the database, because there is still no endpoint to change a member's role (6.1 gap).
- No refresh, registration or route protection yet (Day 3). An expired token sends the person to `/login?expired=1`.
- API responses are cast to my own types (`src/lib/types.ts`), because the generated OpenAPI says the role and frequency enums are integers while the API sends strings.
- The `@theme` warning in `npm run build` comes from the Tailwind CSS setup of the generated template. The build succeeds.

'use server';

import { redirect } from 'next/navigation';
import { deleteSession, getSession } from '@/lib/session';

// Tells the API to log out (with the refresh token), deletes our cookie, goes to /login.
export async function signOut(): Promise<void> {
  const session = await getSession();
  if (session) {
    try {
      // The API reads the refresh token from the "rondi_refresh" cookie on this request.
      await fetch(`${process.env.API_BASE_URL}/api/auth/logout`, {
        method: 'POST',
        headers: { Cookie: `rondi_refresh=${session.refreshToken}` },
        cache: 'no-store',
      });
    } catch {
      // Even if the API is down, we still delete the local session below.
    }
  }
  await deleteSession();
  redirect('/login');
}

'use server';

import { redirect } from 'next/navigation';
import { createSession } from '@/lib/session';
import { correlationIdFrom } from '@/lib/errors';
import { loginMessageFor, messageFor } from '@/lib/errorMessages';

export type SignInState = { error?: string; correlationId?: string };

// The name of the refresh cookie the API sets (AuthConstants.RefreshCookieName).
const REFRESH_COOKIE_NAME = 'rondi_refresh';

// Finds the refresh token value inside the Set-Cookie headers of the login response.
function findRefreshToken(setCookies: string[]): string | null {
  const header = setCookies.find((c) => c.startsWith(`${REFRESH_COOKIE_NAME}=`));
  if (!header) return null;
  return header.split(';')[0].slice(REFRESH_COOKIE_NAME.length + 1);
}

export async function signIn(_prev: SignInState, formData: FormData): Promise<SignInState> {
  const email = String(formData.get('email') ?? '');
  const password = String(formData.get('password') ?? '');
  const base = process.env.API_BASE_URL;

  // 1. Ask the API to log in.
  const res = await fetch(`${base}/api/auth/login`, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ email, password }),
    cache: 'no-store',
  });

  // Wrong password etc: show the friendly message and the reference.
  if (!res.ok) {
    const body = await res.json().catch(() => null);
    return { error: loginMessageFor(res.status), correlationId: correlationIdFrom(body) };
  }

  const body = (await res.json()) as { accessToken?: unknown };
  const accessToken = body.accessToken;
  const refreshToken = findRefreshToken(res.headers.getSetCookie());
  if (typeof accessToken !== 'string' || !refreshToken) {
    return { error: messageFor(500) };
  }

  // 2. Ask the API who this is.
  const meRes = await fetch(`${base}/api/me`, {
    headers: { Authorization: `Bearer ${accessToken}` },
    cache: 'no-store',
  });
  if (!meRes.ok) {
    const meBody = await meRes.json().catch(() => null);
    return { error: messageFor(meRes.status), correlationId: correlationIdFrom(meBody) };
  }
  const me = (await meRes.json()) as { id: string; email: string; fullName: string };

  // 3. Keep everything in the encrypted cookie. No role is stored.
  await createSession({
    accessToken,
    refreshToken,
    user: { id: me.id, email: me.email, displayName: me.fullName },
  });

  // redirect() works by throwing, so it must stay outside any try/catch.
  redirect('/dashboard/member');
}

// Turns a result into data, or into the right response:
// 401 -> /login?expired=1, 404 -> not-found page, anything else -> ApiError (friendly message + reference).
// T is the shape I expect (from src/lib/types.ts).
export function unwrap<T>(result: { data?: unknown; error?: unknown; response: Response }): T {
  const { data, error, response } = result;
  if (response.status === 401) redirect('/login?expired=1');
  if (response.status === 404) notFound();
  if (!response.ok || data === undefined) {
    throw new ApiError(response.status, correlationIdFrom(error));
  }
  return data as T;
}

import 'server-only'; // Build error if a Client Component ever imports this file.
import { cookies } from 'next/headers';
import { EncryptJWT, jwtDecrypt } from 'jose';

// Everything we keep about the signed-in person. NO role here: a role belongs to a person AND a stokvel,
// so it comes from the API for each stokvel.
export type SessionData = {
  accessToken: string;
  refreshToken: string;
  user: { id: string; email: string; displayName: string };
};

const COOKIE_NAME = 'session';
const MAX_AGE_SECONDS = 60 * 60 * 24 * 7; // 7 days (same as the API's refresh token)

// Reads the 32-byte secret from .env.local. Stops loudly if it is missing or the wrong size.
function getKey(): Uint8Array {
  const secret = process.env.SESSION_SECRET;
  if (!secret) throw new Error('SESSION_SECRET is not set');
  const key = Buffer.from(secret, 'base64');
  if (key.length !== 32) throw new Error('SESSION_SECRET must be 32 bytes, base64 encoded');
  return new Uint8Array(key);
}

// Checks that decrypted data really has the shape of SessionData.
function isSessionData(value: unknown): value is SessionData {
  if (!value || typeof value !== 'object') return false;
  const v = value as Record<string, unknown>;
  const u = v.user as Record<string, unknown> | undefined;
  return (
    typeof v.accessToken === 'string' &&
    typeof v.refreshToken === 'string' &&
    !!u &&
    typeof u.id === 'string' &&
    typeof u.email === 'string' &&
    typeof u.displayName === 'string'
  );
}

// Encrypts the data (dir + A256GCM) and stores it in the HttpOnly cookie.
export async function createSession(data: SessionData): Promise<void> {
  const jwt = await new EncryptJWT({ data })
    .setProtectedHeader({ alg: 'dir', enc: 'A256GCM' })
    .setIssuedAt()
    .setExpirationTime(`${MAX_AGE_SECONDS}s`)
    .encrypt(getKey());

  const store = await cookies();
  store.set('session', jwt, {
    httpOnly: true, // JavaScript in the browser cannot read it
    secure: true, // only sent over HTTPS (Chrome also allows it on localhost)
    sameSite: 'lax',
    path: '/',
    maxAge: MAX_AGE_SECONDS,
  });
}

// Reads the cookie. A bad cookie (cannot decrypt, wrong shape) counts as no session at all.
export async function getSession(): Promise<SessionData | null> {
  const store = await cookies();
  const token = store.get(COOKIE_NAME)?.value;
  if (!token) return null;
  try {
    const { payload } = await jwtDecrypt(token, getKey());
    return isSessionData(payload.data) ? payload.data : null;
  } catch {
    return null;
  }
}

// Deletes the cookie (used when signing out).
export async function deleteSession(): Promise<void> {
  const store = await cookies();
  store.delete(COOKIE_NAME);
}

type Shown = {
  lines: string[];
  correlationId: string | null;

};

// Turns any error into what the person sees. Reuses describeError for everything it already knows.
function explain(error: unknown): Shown {
  const d = describeError(error);
  const detail =
    error instanceof ApiError && typeof error.problem?.detail === 'string' ? error.problem.detail : null;
  const base = { correlationId: d.correlationId, fieldErrors: d.fieldErrors };

  // No answer at all: the payment may or may not have been recorded
  if (d.kind === 'network') {
    return {
      ...base,
      mayHaveLanded: true,
      lines: [
        'We did not get an answer, so your payment may have gone through. Your details are kept. Trying again is safe: it will not pay twice.',
      ],
    };
  }
  if (error instanceof ApiError && error.status === 429) {
    return {
      ...base,
      mayHaveLanded: true,
      lines: [`${rateLimitMessage(parseRetryAfter(error.retryAfter))} Your details are kept, and trying again is safe.`],
    };
  }
  if (error instanceof ApiError && error.status >= 500) {
    return {
      ...base,
      mayHaveLanded: true,
      lines: [
        'RondiTrack had a problem, so your payment may have gone through. Your details are kept. Trying again is safe: it will not pay twice.',
      ],
    };
  }
  // 400 / 403 / 409 / 422: show the API's own detail (it explains why)
  if (error instanceof ApiError && [400, 403, 409, 422].includes(error.status)) {
    return { ...base, mayHaveLanded: false, lines: [detail ?? d.message] };
  }
  return { ...base, mayHaveLanded: false, lines: [d.message] };
}

// NEW 7.4: remembers the Idempotency-Key for ONE intent to pay.
// Plain TypeScript (no React) so the MSW tests drive the real thing.
export function createIntentKeeper(makeKey: () => string = () => crypto.randomUUID()) {
  // The key lives inside this keeper (one per form), not in a module variable and not in the TanStack cache.
  let current: { key: string; fingerprint: string } | null = null;

  return {
    // Same fingerprint (same member + cycle + amount) = same key. Anything changed = a NEW key.
    // The key is only made when someone submits, never during render, so StrictMode's double render can't make two.
    keyFor(fingerprint: string): string {
      if (!current || current.fingerprint !== fingerprint) {
        current = { key: makeKey(), fingerprint };
      }
      return current.key;
    },
    // Forget the key: the intent finished (success) or was definitely rejected (400/403/404/409/422).
    release() {
      current = null;
    },
  };
}

// NEW 7.4: ties the key logic to the generated client. One submitter per form instance.
import { ApiError } from '../api/apiError';
import { api, unwrap } from '../api/client';
import { createIntentKeeper } from './intentKey';

export type SubmitInput = {
  stokvelId: string;
  cycleId: string;
  userId: string; // the member the money is for (the API calls it userId)
  amountInCents: number; // integer cents, always a number
};

// Did we get NO real answer, so the money may have been recorded? Then the key must be kept for the retry.
// 401 (authFetch already tried a refresh), 429 (a rejected request does not use up its key), 5xx, dropped connection.
// A real answer (400, 403, 404, 409, 422) means we know nothing was recorded, so the next try is a fresh intent.
export function keepsKey(error: unknown): boolean {
  if (error instanceof ApiError) {
    return error.status === 401 || error.status === 429 || error.status >= 500;
  }
  return error instanceof TypeError; // fetch rejected: network error, outcome unknown
}

export function createContributionSubmitter() {
  const keeper = createIntentKeeper();

  return async function submit(input: SubmitInput) {
    // Same member + cycle + amount = same intent = same key. Change any of them = new key.
    const fingerprint = `${input.stokvelId}|${input.cycleId}|${input.userId}|${input.amountInCents}`;
    const idempotencyKey = keeper.keyFor(fingerprint);

    try {
      // The header comes from the OpenAPI document, so the generated client types and sends it.
      const result = await unwrap(
        await api.POST('/api/v1/stokvels/{stokvelId}/cycles/{cycleId}/contributions', {
          params: {
            path: { stokvelId: input.stokvelId, cycleId: input.cycleId },
            header: { 'Idempotency-Key': idempotencyKey },
          },
          body: { userId: input.userId, amountInCents: input.amountInCents },
        }),
      );
      keeper.release(); // success (even a replayed 201): this intent is done, the next payment gets a NEW key
      return result;
    } catch (error) {
      if (!keepsKey(error)) keeper.release();
      throw error;
    }
  };
}

const recorded = { id: 'c1', stokvelId: 's1', userId: 'm1', cycleId: 'cy1', amount: 150.5, recordedAtUtc: '2026-10-25T10:00:00Z' };

// What the fake server saw on each request to the contributions endpoint
let keysSeen: (string | null)[] = [];
let authSeen: (string | null)[] = [];
let bodiesSeen: unknown[] = [];
let attempt = 0;

const server = setupServer(
  // the real login() runs against this
  http.post(`${API_BASE_URL}/api/v1/auth/login`, () => HttpResponse.json({ accessToken: 'token-1' })),
  // authFetch's refresh runs against this

beforeEach(async () => {
  keysSeen = [];
  authSeen = [];
  bodiesSeen = [];
  attempt = 0;
  __resetSessionForTests();
  await login('treasurer@test.local', 'password'); // real login, fake network
});

// Records what arrived, then lets each test choose the response for attempt n
function contributionsHandler(respond: (n: number) => Response) {
  return http.post(CONTRIBUTIONS, async ({ request }) => {
    keysSeen.push(request.headers.get('Idempotency-Key'));
    authSeen.push(request.headers.get('Authorization'));
    bodiesSeen.push(await request.clone().json());
    attempt++;
    return respond(attempt);
  });
}

const created = () => HttpResponse.json(recorded, { status: 201 });
const input = { stokvelId: 's1', cycleId: 'cy1', userId: 'm1', amountInCents: 15050 };

describe('recording a contribution', () => {
  it('1. a retry after a network error sends the same key', async () => {
    // First attempt never gets an answer: a dropped connection
    server.use(contributionsHandler((n) => (n === 1 ? HttpResponse.error() : created())));
    const submit = createContributionSubmitter();

    await expect(submit(input)).rejects.toBeInstanceOf(TypeError);
    await submit(input); // the person clicks "Try again", nothing changed

    expect(keysSeen).toHaveLength(2);
    expect(keysSeen[0]).not.toBeNull();
    expect(keysSeen[1]).not.toBeNull();
    expect(keysSeen[0]).toBe(keysSeen[1]);
  });

  it('2. the next contribution gets a new key', async () => {
    server.use(contributionsHandler(() => created()));
    const submit = createContributionSubmitter();

    await submit(input);
    await submit(input); // a second, new payment

    expect(keysSeen).toHaveLength(2);
    expect(keysSeen[0]).not.toBe(keysSeen[1]);
  });

  it('3. a 429 keeps the key and exposes the wait', async () => {
    server.use(
      contributionsHandler((n) =>
        n === 1
          ? HttpResponse.json({ title: 'Too many requests' }, { status: 429, headers: { 'Retry-After': '1' } })
          : created(),
      ),
    );
    const submit = createContributionSubmitter();

    const error = await submit(input).catch((e: unknown) => e);
    expect(error).toBeInstanceOf(ApiError);
    expect((error as ApiError).status).toBe(429);
    expect(parseRetryAfter((error as ApiError).retryAfter)).toBe(1); // the form shows this wait

    await submit(input); // after the wait
    expect(keysSeen[0]).not.toBeNull();
    expect(keysSeen[0]).toBe(keysSeen[1]);
  });

  it('4. changing the amount after a failure is a new intent', async () => {
    server.use(contributionsHandler((n) => (n === 1 ? HttpResponse.error() : created())));
    const submit = createContributionSubmitter();

    await expect(submit(input)).rejects.toBeDefined();
    await submit({ ...input, amountInCents: 20000 }); // the person corrected the amount

    expect(keysSeen[0]).not.toBe(keysSeen[1]);
    expect(bodiesSeen[1]).toMatchObject({ amountInCents: 20000 });
  });

  it('5. a 401 retry keeps the key and uses the new token', async () => {
    server.use(
      contributionsHandler((n) => (n === 1 ? new HttpResponse(null, { status: 401 }) : created())),
    );
    const submit = createContributionSubmitter();

    await submit(input); // authFetch refreshes and retries by itself

    expect(keysSeen).toHaveLength(2);
    expect(keysSeen[0]).not.toBeNull();
    expect(keysSeen[1]).toBe(keysSeen[0]);
    expect(authSeen[0]).toBe('Bearer token-1');
    expect(authSeen[1]).toBe('Bearer token-2'); // the new token
  });

  it('6. cents survive the trip: "150.50" is sent as the number 15050', async () => {
    server.use(contributionsHandler(() => created()));
    const submit = createContributionSubmitter();

    await submit({ ...input, amountInCents: parseRandsToCents('150.50')! });

    const body = bodiesSeen[0] as { amountInCents: unknown };
    expect(body.amountInCents).toBe(15050);
    expect(typeof body.amountInCents).toBe('number');
  });
});

// NEW: turns an integer number of cents into "R 150,50" without ever using fractional floats.
const zarFormatter = new Intl.NumberFormat('en-ZA', {
  style: 'currency',
  currency: 'ZAR',
})

export function formatCents(cents: number): string {
  // Reject 10.5, NaN, Infinity, or numbers too big to be exact
  if (!Number.isSafeInteger(cents)) {
    throw new Error('not a whole number of cents')
  }

  // BigInt keeps everything as whole numbers, so there is no float rounding at all
  const big = BigInt(cents)
  const negative = big < 0n
  const abs = negative ? -big : big

  // Integer division and remainder: 15050 cents -> 150 rands and 50 cents
  const rands = abs / 100n
  const rest = abs % 100n

  // Build an exact decimal string like "150.50" (pad so 5 cents becomes "05")
  const decimal = `${negative ? '-' : ''}${rands}.${rest.toString().padStart(2, '0')}`

  // Intl accepts an exact decimal string, so it formats without turning it into a float
  return zarFormatter.format(decimal as `${number}`)
}

// Step 7 name: later files import formatRand, so it forwards to formatCents
export function formatRand(value: number): string {
  return formatCents(value)
}

// NEW: formats dates in South African time, whatever time zone the laptop is set to.
const TIME_ZONE = 'Africa/Johannesburg'

// "01 Nov 2026, 00:30"
const dateTimeFormatter = new Intl.DateTimeFormat('en-ZA', {
  dateStyle: 'medium',
  timeStyle: 'short',
  timeZone: TIME_ZONE,
})

// "01 Nov 2026"
const dateFormatter = new Intl.DateTimeFormat('en-ZA', {
  dateStyle: 'medium',
  timeZone: TIME_ZONE,
})

// Matches a plain calendar date like "2026-10-31" (no time, no Z)
const CALENDAR_DATE = /^\d{4}-\d{2}-\d{2}$/

function toDate(value: string): Date {
  // A plain calendar date is already a South African day. Noon UTC (14:00 in SA)
  // means no time zone can push it onto the wrong day.
  const date = CALENDAR_DATE.test(value) ? new Date(`${value}T12:00:00Z`) : new Date(value)
  if (Number.isNaN(date.getTime())) {
    throw new Error(`not a valid date: ${value}`)
  }
  return date
}

// For UTC instants like "2026-10-31T22:30:00Z" (date AND time, in SA time)
export function formatDateTime(value: string): string {
  return dateTimeFormatter.format(toDate(value))
}

// Date only. Works with both a UTC instant and a calendar date
export function formatDate(value: string): string {
  return dateFormatter.format(toDate(value))
}

import { ApiError } from '../api/apiError';

export type ErrorKind =
  | 'network'
  | 'rateLimited'
  | 'badCredentials'
  | 'sessionEnded'
  | 'notFound'
  | 'validation'
  | 'generic';

export type DescribedError = {
  kind: ErrorKind;
  title: string;
  message: string;
  correlationId: string | null; // null = there is no reference to show
  retryAfterSeconds: number | null;
  fieldErrors: Record<string, string[]>; // keys are lower-case, e.g. "email"
};

// Retry-After is either seconds ("23") or an HTTP date. Returns seconds or null.
export function parseRetryAfter(header: string | null | undefined, now: number = Date.now()): number | null {
  if (!header) return null;
  const text = header.trim();
  if (/^\d+$/.test(text)) return Number(text);
  const when = Date.parse(text);
  if (Number.isNaN(when)) return null;
  return Math.max(0, Math.ceil((when - now) / 1000)); // date in the past = 0
}

export function rateLimitMessage(seconds: number | null): string {
  if (seconds === null) return 'Too many requests. Please wait a moment and try again.';
  return `Too many requests. Try again in ${seconds} ${seconds === 1 ? 'second' : 'seconds'}.`;
}

const asString = (v: unknown): string | null => (typeof v === 'string' && v ? v : null);

// Turns ANY error into plain words. Never uses the "detail" field (it can leak internals on a 500).
export function describeError(error: unknown, context: 'data' | 'login' = 'data'): DescribedError {
  const empty = { correlationId: null, retryAfterSeconds: null, fieldErrors: {} };

  // fetch itself failed (API down, no internet): there is no response and no reference
  if (error instanceof TypeError) {
    return {
      ...empty,
      kind: 'network',
      title: "Can't reach RondiTrack",
      message: 'Check your connection.',
    };
  }

  if (!(error instanceof ApiError)) {
    return {
      ...empty,
      kind: 'generic',
      title: 'Something went wrong',
      message: 'Something went wrong on our side. Please try again.',
    };
  }

  const correlationId = asString(error.problem?.correlationId);
  const base = { ...empty, correlationId };

  if (error.status === 429) {
    const seconds = parseRetryAfter(error.retryAfter);
    return {
      ...base,
      kind: 'rateLimited',
      title: 'Too many requests',
      message: rateLimitMessage(seconds),
      retryAfterSeconds: seconds,
    };
  }
  if (error.status === 401) {
    return context === 'login'
      ? { ...base, kind: 'badCredentials', title: 'Sign in failed', message: 'Email or password is incorrect.' }
      : { ...base, kind: 'sessionEnded', title: 'Session ended', message: 'Please sign in again.' };
  }
  if (error.status === 404) {
    return {
      ...base,
      kind: 'notFound',
      title: 'Stokvel not found',
      message: "This stokvel doesn't exist, or you are not a member of it.",
    };
  }
  if (error.status === 400) {
    const fieldErrors: Record<string, string[]> = {};
    const raw = error.problem?.errors;
    if (raw && typeof raw === 'object') {
      for (const [key, value] of Object.entries(raw)) {
        if (Array.isArray(value)) fieldErrors[key.toLowerCase()] = value.map(String);
      }
    }
    return { ...base, kind: 'validation', title: 'Please check your details', message: 'Some fields need your attention.', fieldErrors };
  }
  return {
    ...base,
    kind: 'generic',
    title: 'Something went wrong',
    message: 'Something went wrong on our side. Please try again in a moment.',
  };
}

// The one error type the whole app uses for failed API calls.
// problem = the problem+json body (read defensively, no hand-written API types).
export class ApiError extends Error {
  readonly status: number;
  readonly problem: Record<string, unknown> | null;
  readonly retryAfter: string | null; // raw Retry-After header text

  constructor(
    status: number,
    problem: Record<string, unknown> | null,
    retryAfter: string | null,
  ) {
    super(
      typeof problem?.title === 'string' ? problem.title : `Request failed with ${status}`,
    );
    this.name = 'ApiError';
    this.status = status;
    this.problem = problem;
    this.retryAfter = retryAfter;
  }
}

// Turns a failed Response into an ApiError (body may be empty, so we guard it)
export async function apiErrorFromResponse(res: Response): Promise<ApiError> {
  let problem: Record<string, unknown> | null = null;
  try {
    const body: unknown = await res.json();
    if (body && typeof body === 'object') problem = body as Record<string, unknown>;
  } catch {
    // no JSON body, that is fine
  }
  return new ApiError(res.status, problem, res.headers.get('Retry-After'));
}
